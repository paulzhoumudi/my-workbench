# 媒体剪辑工作台（dsh-media-workbench）

DSH Desktop 工作台插件，落地《DSH-Desktop 媒体自动化剪辑工作台 · 产品方案 v0.2》：**左边看结果，右边跟 AI 说**。

- **项目栏**：项目下拉（搜索 / 新建 / 打开已有文件夹 / 归档 / 移出列表 / 路径失效重新定位），显示画幅规格与 FFmpeg、Eagle、剪映连接状态。
- **创意**：`01_creative` 文件树 + Markdown 预览 / 编辑；每次 AI 改写自动把旧版本存入 `_history`，可对比、回滚；文案和分镜可「设为剪辑使用版本」；分镜缺「所需标签」的镜头标黄。
- **素材**：导入 → 清洗（清晰度、抖动、过短、黑屏、重复，每条丢弃都有量化依据，原片永不移动）→ 镜头切片（1080p 代理 + 缩略图）→ AI 打标（只能从标签字典里选，字典外进「待审」，置信度 < 0.6 标「待复核」）→ 网格复核（键盘 ← → Enter）→ Eagle 入库 / 拉回；标签改名、合并、删除会同步全部切片并标记 Eagle 待同步；显示 AI 标签采纳率。
- **剪辑**：输出规格、剪辑思路、分镜 × 素材匹配（Top3 可替换，低于 0.6 不自动选用）、缺口清单、引擎无关的 `timeline.json`、FFmpeg 粗剪预览 / 原片直出（附 `manifest.json` 与 SRT）。
- **AI 对话栏**：上下文条（项目 · 当前 Tab · 文案 / 分镜版本）、随 Tab 变化的快捷指令、DSH 原生会话；Agent 通过 24 个 `media_*` 工具操作项目，覆盖文件、改标签、清洗、恢复、同步 Eagle、正式渲染前会弹出确认并写明影响条数。

## 安装

需要 DSH Desktop（Harness 0.1.5 及以上）和本机 FFmpeg。

1. **装 FFmpeg**（Windows）：在终端运行 `winget install Gyan.FFmpeg`，装好后重启 DSH Desktop。没有加入 PATH 时，可以在工作台右上角 ⚙ 设置里填写 `ffmpeg.exe` 路径。
2. **装工作台插件**，任选一种：
   - 在 DSH Desktop 里打开「设置 → 插件」，用安装入口填写安装包的完整路径，例如
     `E:\视频创作\工作台\旗舰版工作台\dsh-media-workbench-0.1.0.tgz`；
   - 或在 DSH Desktop 的普通对话里对 Agent 说：「请用插件安装工具安装本地插件包 E:\视频创作\工作台\旗舰版工作台\dsh-media-workbench-0.1.0.tgz」。
3. **完整退出并重新打开 DSH Desktop**。
4. 展开左侧栏，点左上角「工作台」右侧的当前工作台名称，选择「媒体剪辑工作台」。没看到的话，到「工作台市场 → 已安装」检查条目和运行状态。

可选：打开 Eagle（同步素材库）；`pip install -U openai-whisper`（本地语音转写）。

## 使用流程

1. 「新建项目」→ 在系统窗口里选择或新建一个文件夹 → 起名、选标签模板（Vlog 基础 / 产品广告 / 你另存的模板）。会建好「原始素材库」「输出素材库」「创意剪辑」三个文件夹和隐藏的 `.dsh/`，已有文件不动。
2. 右侧「为这个项目开始对话」，然后用快捷指令或直接说：出创意 → 写文案 → 出分镜。
3. 标签 Tab：可以换模板、编辑模板、把本项目的标签另存为新模板；点「根据素材建议标签」让 AI 看素材，建议的新标签先进「待审」，你转正后才参与打标和匹配。点某个标签可以看用到它的切片，并改名 / 合并 / 移动维度 / 删除。
4. 把素材放进 `原始素材库`，在素材 Tab 点「导入素材」「清洗」「镜头切片」，再让 AI 打标，复核后同步 Eagle。
5. 剪辑 Tab 设输出规格（画幅、分辨率、帧率、目标时长等）→ 按分镜匹配素材 → 处理缺口 → 生成时间线 → FFmpeg 粗剪预览 / 直出。

## 项目文件夹结构

```
项目文件夹/
├── 原始素材库/                原片（只读）
├── 输出素材库/
│   ├── 切片素材/<原片>/        清洗切片后的 1080p 代理片段
│   └── 成片/                  导出的成片、字幕、*.manifest.json
├── 创意剪辑/
│   ├── 00_主题简报.md 01_创意方向.md 02_文案.md 03_分镜脚本.md 剪辑思路.md 缺口清单.md
│   ├── 参考资料/
│   ├── 剪辑数据/              edit_spec.json、match.json、timeline.json、subtitles.srt
│   └── _history/
└── .dsh/                     隐藏：project.json、index.json、creative.json、log/
    └── tags/                  标签字典.yaml（含待审区）、清洗报告.json、丢弃登记/、_history/
```

标签不再是文件夹，统一在面板的「标签」Tab 管理；标签模板是全局的，存在工作台自己的数据目录（`tag-templates.json`），所有项目共用。

左侧文件树展示项目文件夹的真实内容；点击某个库（或对话栏上方的「工作目录」按钮），右侧对话就切换到那个文件夹里进行，每个库各保留一条对话。旧版项目（00_brief ~ 06_export，或带「标签管理」文件夹的 0.1.3）打开时会自动迁移到这个结构：原片不移动，「标签管理」里的字典、报告、丢弃登记移进 `.dsh/tags/`，你自己放进去的其他文件原地保留。

## 与方案 v0.2 的差异（当前版本）

- 剪映草稿：格式为社区逆向，需先在你使用的剪映版本上验证（方案 M0），本版暂未接入；`timeline.json` 已保留转场等信息，目前用 FFmpeg 出片。
- 索引用 `.dsh/index.json` 代替 SQLite（免原生依赖）。
- 打标用你在 DSH 里配置的模型看关键帧拼图（`media_keyframes` → `media_tag_clips`），不单独接通义 Qwen-VL；模型不支持看图时会如实说明。
- FFmpeg 出片按硬切处理；叠化写在时间线里，留给剪映精修。
- 平台按 Windows 适配（也兼容 macOS）。

## 开发

```bash
npm install          # 只装构建依赖（esbuild、react、yaml）
npm run build        # src/ → dsh/index.js（服务端）+ lib/client.js（客户端单文件）
npm test             # 需要 PATH 里有 ffmpeg/ffprobe
node test/harness/serve.mjs 4870   # 不开 DSH 也能在浏览器里调试面板（模拟宿主 + 演示项目）
pnpm pack            # 生成安装包
```

工作台身份目前用占位仓库 `https://github.com/dsh-local/dsh-media-workbench`（见 `src/client/index.jsx` 的 `REPOSITORY`）；上架工作台市场前改成真实仓库地址。
