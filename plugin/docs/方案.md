# 素材清洗台：广告拍摄素材 AI 清洗方案

> 本文是 0.1.0 的原始方案。0.2.0 的实际功能、验证状态和安全分级说明以项目根目录 README 为准；短片段现进入 B 级，按需视频预览和校准工具已加入。

版本 0.1.0 · 2026-10-26 · 以 DSH Desktop 工作台插件形式交付（包名 `dsh-footage-culler`）

## 1. 要解决的问题

广告片组每天产出几小时甚至几十小时素材，由人工逐条看、逐条挑，耗时多，而且容易漏看。目标是让 AI 先把明显的废片挡在外面，再对剩下的素材按「能不能用、好不好看」排序，人只需要复核有疑问的部分。

方案遵守三条原则：

1. **只分级，不删除**。原始素材全程只读，插件里没有任何删除、移动或转码原片的代码路径。删不删由人决定。
2. **按秒判断**。一条 take 可能前半段对焦过程虚焦、后半段完美，所以按 1 秒窗口打分，输出可用的入点和出点，不对整条素材下结论。
3. **人工改判会被记录下来**。导演每一次改判都写入 `feedback.ndjson`，作为后续校准团队审美的数据。

## 2. 总体架构：三层漏斗

```
素材文件夹（只读）
   │  ffmpeg 一次解码出两路灰度帧：10fps 小图（看运动）+ 2fps 大图（看清晰度）
   ▼
第一层 技术过滤（本地运行，全部素材都跑）
   虚焦/跑焦 · 抖动 · 过曝/欠曝 · 黑场/遮挡 · 硬切点
   → 1 秒窗口 → 连续可用区段（候选片段）+ 技术废片区段
   ▼
第二层 批次基准（同机型/同编码的一批素材之间做对比）
   清晰度以本批第 75 百分位为"清晰"的标准，自动适配不同机身、编码和场景
   ▼
第三层 AI 复审（可选，只看候选片段）
   每段抽 4 帧静帧 → 多模态大模型（OpenAI 兼容接口）按团队审美标准输出结构化 JSON：
   是否可用 · 审美分 · 构图分 · 主体 · 景别 · 运镜 · 问题（场记板/穿帮/主体出画…）· 标签 · 理由
   ▼
分级：A 直接可用 / B 需复核 / C 归档（每段都附理由）
   ▼
导出：FCPXML（Final Cut、达芬奇）· FCP7 XML（Premiere、达芬奇）· CSV 场记表 · JSON
```

## 3. 第一层：技术检测怎么避免误判

| 问题 | 做法 | 避免的误判 |
|---|---|---|
| 虚焦 | 测"边缘宽度"：在有边缘的位置，用拉普拉斯响应除以梯度强度。画面越清晰，边缘越窄，这个值越大；跟画面对比度无关。只取最清晰的 10% 区块 | **浅景深**（主体清楚、背景虚化）不判虚焦；**LOG 灰片**不会因为对比度低被判虚焦 |
| 噪点 | 先算出平坦区域的噪声底，从测量值里扣掉 | **高 ISO 颗粒**不会被当成"细节"，掩盖真实的虚焦 |
| 抖动 | 9 个区域各自做投影匹配，取中位数，得到整个画面的位移轨迹；再减去 0.8 秒平滑后的轨迹，剩下的高频残差就是抖动 | **推拉摇移、稳定器运镜**不算抖动；画面里单个移动物体不会被当成镜头晃动；纯色背景和重复纹理（白棚、测试图）匹配不可信时直接跳过 |
| 曝光 | 统计高光和暗部被裁切的像素比例，以及平均亮度；LOG 模式下不判欠曝 | LOG 素材不会整批被判"欠曝" |
| 黑场/遮挡 | 低亮度且低方差，或者画面几乎没有变化 | — |
| 硬切 | 直方图突变点 | 跨切点的区段不合并；抖动轨迹在切点处重新开始计算 |

分析用帧只用于计算。需要的话可以在设置里指定一个 `.cube` LUT 套在分析帧上，原片不受影响。

### 合成样片校准结果（`npm test`，全部通过）

| 样片 | 预期 | 结果 |
|---|---|---|
| 清晰静止 / 4K 测试图 | A | A |
| 略软（σ2.2）/ 虚焦（σ5）| C 虚焦 | C 虚焦 |
| 手持抖动 | C 抖动 | C 抖动 |
| 轻微晃动 | B（提示：轻微晃动）| B |
| 平滑横移运镜 | 不判抖动 | 通过（AI 审美 6 分，进 B）|
| 浅景深 | A | A |
| 过曝 | C 过曝 | C |
| LOG 风格低对比 | A | A |
| 开头 2 秒黑场 + 清晰 | 0–2s C，后段可用 | 符合 |
| 前 3 秒清晰、后 3 秒失焦 | 0–3s A，3–6s C | 符合 |
| 白棚产品静止 / 白棚抖动 / 白棚虚焦 | A / C / C | 符合 |
| 虚焦 + 高 ISO 颗粒 / 清晰 + 颗粒 | C / A | 符合 |

清晰度梯度：σ0.8 → 不扣分，σ1.2 → B（略软），σ1.6 → 部分 C。

**这些阈值目前只在合成素材上校准过**。拿到真实素材以后，要用 `node test/calibrate.mjs <素材目录>` 把各项指标打印出来，跟人工结论对比后再调整（见第 8 节）。

### 速度（Apple M3 Pro 实测）

- 4K H.264，30 秒素材：约 1.0 秒完成技术检测（约 30 倍实时）
- 4K HEVC 10bit，30 秒素材：约 5 秒（约 6 倍实时）

按这个速度，一天 5 小时 4K 素材的技术检测大约需要 10–50 分钟，取决于编码格式。AI 复审的耗时另算，取决于模型和并发数。

## 4. 第三层：AI 复审

- 接口是标准的 OpenAI Chat Completions 格式，以下模型都可以直接接：
  - 私有部署：Qwen3-VL（vLLM、Ollama、LM Studio），客户素材建议优先用这种方式
  - 云端接口：阿里云百炼 Qwen-VL、腾讯混元多模态、豆包视觉、Gemini 的 OpenAI 兼容端点
- 每段默认抽 4 帧，每帧缩放到 768 宽的 JPEG 发给模型。可以设置"最多复审片段数"，超出时只复审技术分最高的那部分，用来控制成本。
- **团队审美标准**可以在设置里直接用中文写，例如"主体必须是食物；要有食欲感（色泽、热气、拉丝）；不能有场记板"。
- 模型返回必须是 JSON。插件会做容错解析和字段裁剪，失败时自动重试一次；如果复审最终失败，只按技术分给级，并在理由里注明。
- API Key 保存在 DSH 宿主凭据库中，不写入任何文件、提示词或日志。分析子进程通过 stdin 拿到 Key。

## 5. 分级规则

| 等级 | 条件 |
|---|---|
| **C 归档** | 技术废片（黑场、虚焦、抖动、过曝、欠曝），或者可用时长短于最短片段（默认 2 秒），或者 AI 判定不可用（场记板、穿帮、主体出画、主体不清、无有效内容） |
| **A 直接可用** | 没有任何技术提示，并且综合分 ≥ 75、AI 审美分 ≥ 7。综合分 = 技术分 × 0.4 + 视觉分 × 0.6，视觉分由审美和构图加权得到。不启用 AI 时，技术分 ≥ 85 且无提示即为 A |
| **B 需复核** | 其余可用片段。典型情况是有轻微晃动、略软、高光溢出等提示，或者审美分中等 |

可以调的参数：严格度（宽松/标准/严格）、最短片段时长、技术分权重。

## 6. 产品形态：DSH Desktop 工作台

按照 DSH 工作台开发规范，采用"业务整页 + 按需会话"布局（`customFrame: true`、`headerLayout: 'compact'`）：

- **顶部工具栏**：添加素材文件夹、设置、AI 协助
- **左栏**：已添加的素材文件夹（每个都有「开始清洗」按钮）和历次清洗记录
- **主区**：
  - 汇总卡片：素材总时长、A/B/C 各自的时长和条数、其中技术废片的时长
  - 每条素材一条质量时间轴：绿色可用，黄色有提示，红色废片
  - 片段卡片：缩略图、入出点、理由、各项分数、景别和标签；每张卡片都可以下拉直接改判
- **导出**：选择等级和格式，用系统目录选择器指定保存位置
- **AI 协助**：用户主动点开时才创建本工作台的会话，嵌入宿主原生的对话界面。可以直接说"清洗一下今天 B 机的素材，告诉我哪些能用""第 3 段改成 A""把 A 和 B 导出成 Premiere 时间线"。

### Agent 工具（对话中可以调用）

| 工具 | 作用 |
|---|---|
| `footage_folders` | 列出已添加的文件夹、近期任务，以及 ffmpeg 是否可用 |
| `footage_scan` | 对已添加文件夹（或其子目录）发起清洗 |
| `footage_job` | 查询进度和结果（最多等待 120 秒），结果按 A/B/C 排序并附理由 |
| `footage_set_grade` | 记录导演改判，同时写入反馈数据 |
| `footage_export` | 把指定等级导出为时间线和场记表，保存在插件数据目录 |

另外附带 `footage-culling` Skill，规定 Agent 用导演的行话汇报结果，并且绝不动原片。

### 安全边界

- 只能扫描用户在界面里通过系统目录选择器添加过的文件夹，用 realpath 判断，防止符号链接绕过。Agent 不能自己新增扫描位置。
- 原片只读。导出时不覆盖已有文件，重名自动加序号。用户指定导出位置时，插件不会自动创建目录。
- 解码和分析在独立子进程中运行，不阻塞 Harness。同一时间只允许一个任务。应用重启后，上次未完成的任务标记为"已中断"。
- 缩略图和任务编号做了严格的格式校验，防止路径穿越。

## 7. 部署建议

| 规模 | 建议 |
|---|---|
| 导演或剪辑师个人使用 | 本机装 DSH Desktop 和 ffmpeg，只用技术检测，或者接一个云端 VLM |
| 片组团队 | 一台工作站（24–32GB 显存）部署 Qwen3-VL，供团队共用；各成员的 DSH 填同一个局域网 API 地址 |
| 拍摄量很大 / 跑夜间批处理 | 直接用命令行 `node engine/cli.mjs scan --input <素材盘> --out <结果目录>` 在存储附近的机器上整夜跑，第二天把结果导入剪辑软件 |

RAW 格式（BRAW、R3D、ARRIRAW）ffmpeg 通常解不了，需要先出代理文件（ProRes Proxy / H.264）再分析。导出的时间线可以在剪辑软件里重新链接回原片。

## 8. 落地路线

| 阶段 | 做什么 | 验收标准 |
|---|---|---|
| **P0 试点（1 周）** | 选 1 个真实项目的 1 天素材加上人工选片结果，跑 `calibrate.mjs`，对比 AI 和人工 | 技术废片召回率 ≥ 90%；A 级的误收率 ≤ 10% |
| **P1 调参（1–2 周）** | 按机型调严格度和阈值，补充 LOG/LUT 设置，写好团队审美标准，接入私有 VLM | 人工需要复核的素材时长下降 ≥ 50% |
| **P2 学习团队审美（持续）** | 用 `feedback.ndjson` 中积累的改判数据，加上历史项目剪辑工程里"用了/没用"的片段，训练一个轻量审美分类器（例如 SigLIP 特征 + 逻辑回归），作为第四层接入 | 模型对 A/C 的判断和导演改判的一致率持续上升 |
| **P3 扩展** | 读取陀螺仪元数据（Gyroflow 支持的机型）提高抖动判断精度；做场记板 OCR，自动填场次和镜号；同一镜头多个 take 横向比较选最佳 | — |

## 9. 已知局限（如实说明）

- 阈值只在合成素材上校准过，第一次用在新机型上需要抽查。
- "审美"判断依赖所接模型的能力和团队写的标准，只能做到初筛和排序，替代不了导演的判断，所以保留了 B 级。
- 抖动检测针对的是平移类抖动，对快速旋转（roll）的判断较弱。
- 清晰度判断对"刻意的柔焦或雾化滤镜"会偏严，可以对这类镜头所在的文件夹用"宽松"档位。
- 尚未在真实 DSH Desktop 中完成安装后的界面验收（见 README 的验收状态）。
